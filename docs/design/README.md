# 모듈 설계

SRS [§2 시스템 구성](../SRS.md#2-시스템-구성)이 **경계**(누가 누구와 무엇을 주고받는가)를 고정한다. 이 디렉터리는 **모듈 하나의 내부 설계**를 다룬다.

## 규칙

- **구현 직전에 쓴다.** 모듈 구현 task를 시작하기 전에 해당 모듈의 설계 문서를 먼저 쓴다. 미리 다 쓰지 않는다 — 안 만들 모듈의 문서는 낭비다.
- **파일 하나 = 모듈 하나** (`<모듈>.md`). 한국어. [`TEMPLATE.md`](TEMPLATE.md)를 복사해 쓴다.
- **SRS가 우선한다.** 설계 문서는 SRS의 UC·FR을 어떻게 만족시키는지만 쓴다. 요구사항이 바뀌면 SRS를 먼저 고친다.
- **구현이 바뀌면 같은 PR에서 고친다.** 코드와 어긋난 설계 문서는 없는 것보다 나쁘다.
- 목록은 표로 관리하지 않는다. 디렉터리 목록이 곧 인덱스이고, 각 문서 상단의 `상태` 항목으로 현황을 읽는다.

## API 계약

[`api.md`](api.md)에 엔드포인트별 요청·응답을 쓴다. FE·BE·AI가 병렬로 일하는 기준이므로 **API를 바꾸기 전에 api.md를 먼저 고치고**, 같은 PR에 코드 변경을 싣는다. 구현 전에는 예시 응답을 그대로 돌려주는 목 서버로 개발한다 — 그 목은 `MOCK(<id>)` 마커와 [`ai-scope.md`](../ai-scope.md) 등록 대상이다.
